8085 MINI ASSEMBLER
===================

A portable C11 command-line program that translates individual supported 8085
instructions into hexadecimal machine-code bytes. It validates syntax, operands,
register combinations and numeric ranges. It does not execute instructions.

Project files
-------------
include\assembler.h       Public result structure and function declarations.
src\assembler.c           Parsing, opcode table, validation and code generation.
src\main.c                Interactive/single-instruction CLI and listing output.
tests\test_assembler.c    Opcode, operand and boundary tests.
tests\test_cli.cjs        Command-line, session, exit-code and file-output tests.
examples\instructions.txt Example interactive-session input, ending with QUIT.
build.ps1                 Windows build and optional C tests.
Makefile                  Linux/GCC build and tests.
build\assembler.exe       Windows executable generated by the build.

Build on Windows
----------------
Install GCC (for example through MinGW-w64), or use an existing Clang compiler.
From PowerShell in this directory:

  .\build.ps1 -Test
  .\build.ps1 -Compiler clang -Test

With an existing Zig compiler:

  .\build.ps1 -Compiler 'C:\path\to\zig.exe' -Test

If Windows blocks local scripts, approve a process-only override before using:

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test

This does not change the machine's execution policy. Alternatively compile
directly without a PowerShell script:

  gcc -std=c11 -Wall -Wextra -Wpedantic -Werror -O2 -Iinclude src\assembler.c src\main.c -o build\assembler.exe

Create the build directory first if compiling directly. Node.js is optional and
used only for the additional command-line integration tests:

  node tests\test_cli.cjs build\assembler.exe

Build on Linux
--------------
Use GCC and Make:

  make
  make test
  ./build/assembler "MVI A,05H"
  node tests/test_cli.cjs build/assembler

The Node integration command is optional. Core C tests require no Node packages.

Run on Windows
--------------
  .\build\assembler.exe
  .\build\assembler.exe "MVI A,05H"
  .\build\assembler.exe "MOV B,A"
  .\build\assembler.exe --list
  .\build\assembler.exe --help
  .\build\assembler.exe --output listing.txt "LDA 2050H"

An output file is a human-readable listing, not an executable, binary ROM image
or Intel HEX file. --output opens/truncates the named file; choose a new filename
or back up an existing listing. Invalid instructions are never emitted as code.

Without a single instruction argument, enter one instruction per line. QUIT
(case-insensitive), or EOF, ends the session. HLT is translated normally; it
does not terminate the assembler. Blank lines and full-line comments are ignored.
The summary counts only successfully translated instructions and their bytes,
with a separate error count. The process exits nonzero if any instruction failed.

Example replay through standard input:

  Get-Content .\examples\instructions.txt | .\build\assembler.exe

This replays individual interactive instructions. It is not full assembly-file
support: there are no labels, symbols, directives, addresses or program linking.
On Linux, use standard input redirection with examples/instructions.txt.

Examples and expected output
----------------------------
Input: MVI A,05H
Opcode       : 3E
Machine Code : 3E 05
Size         : 2 Bytes

Input: MOV B,A
Opcode       : 47
Machine Code : 47
Size         : 1 Byte

Input: LDA 2050H
Opcode       : 3A
Machine Code : 3A 50 20
Size         : 3 Bytes

Input: XYZ A,B
Error: Unknown or unsupported mnemonic 'XYZ'.

Syntax and numeric rules
------------------------
Mnemonics/registers are case-insensitive. Spaces around commas are allowed.
Operands must be comma-separated single tokens. A semicolon begins a comment.

  MVI A,05H          Hexadecimal with suffix H.
  MVI A,0x05         Hexadecimal with prefix 0x.
  MVI A,5            Decimal.
  MVI A,10           Decimal ten, encoded as 0A.
  MVI A,10H          Hexadecimal sixteen, encoded as 10.

Do not combine prefix and suffix (0x10H). Signed, fractional, binary and symbolic
operands are unsupported. Bare hexadecimal letters require H or 0x.
Byte operands are 0..255; words/addresses are 0..65535; RST vectors are 0..7.
16-bit values are emitted low byte first, as required by the 8085.
Maximum line length: 255 characters excluding the line ending.

Registers and pairs
-------------------
Single registers: B, C, D, E, H, L, M, A.
M refers to memory addressed by HL; it is not another physical register.
MOV M,M is rejected because opcode 76H is HLT, not a valid MOV.
LXI/INX/DCX/DAD pairs: B, D, H, SP.
PUSH/POP pairs: B, D, H, PSW (not SP).
STAX/LDAX pairs: B or D only.
Use canonical 8085 pair names, not BC/DE/HL aliases.

Supported instruction families
------------------------------
No operand:
  NOP HLT DI EI RIM SIM RLC RRC RAL RAR DAA CMA STC CMC XCHG XTHL SPHL PCHL
  RET RNZ RZ RNC RC RPO RPE RP RM
Register:
  ADD ADC SUB SBB ANA XRA ORA CMP INR DCR
Register transfer/immediate:
  MOV MVI
Register pair:
  LXI INX DCX DAD PUSH POP STAX LDAX
8-bit immediate/port:
  ADI ACI SUI SBI ANI XRI ORI CPI IN OUT
16-bit address:
  LDA STA LHLD SHLD JMP JNZ JZ JNC JC JPO JPE JP JM
  CALL CNZ CZ CNC CC CPO CPE CP CM
Restart:
  RST

The opcode table stores a base opcode and operand format. Register-specific
opcodes are calculated using the 8085 encoding's bit fields; tests enumerate
the register combinations. Undocumented instructions are intentionally excluded.

Exit codes
----------
0: Successful translation/session, instruction list, or help.
1: Invalid assembly input, input/output failure, or unsuccessful session.
2: Invalid command-line usage.

Testing and scope
-----------------
The C tests cover the opcode table, all MOV register combinations, arithmetic,
register-pair instructions, numeric boundaries, case/whitespace handling,
invalid operands, and safe clearing of a failed result.
Integration tests cover CLI outputs, session totals, comments/QUIT/HLT,
overlong input recovery, exit codes, and listing-file errors.
The API requires non-NULL input and result pointers.

Future improvements: labels, symbol tables, two-pass assembly, ORG/DB directives,
source-file assembly, address-aware listings, binary/Intel HEX export and a CPU
simulator. These are not implemented. Single-instruction listing output is
implemented now and is distinct from an executable machine-code file.
